# คู่มือติดตั้งและ Deploy — ระบบตรวจนับทรัพย์สิน BRH3

ทำครั้งเดียวตอนเริ่มระบบ ใช้เวลาประมาณ 30–40 นาที ทำตามลำดับ **ห้ามข้ามขั้น**

---

## ขั้นที่ 1 — สร้าง Supabase Project ใหม่ (บัญชีเดิมที่ใช้กับ MCR)

1. เข้า https://supabase.com/dashboard ด้วยบัญชีเดิม
2. กด **New project** (อยู่ในหน้า organization เดิมได้เลย)
3. กรอก:
   - **Name**: `asset-verify-brh3`
   - **Database Password**: ตั้งรหัสแล้ว**จดเก็บไว้** (ใช้ตอนกู้ระบบ ไม่ได้ใช้ตอนใช้งานปกติ)
   - **Region**: `Southeast Asia (Singapore)` — เหมือน MCR ให้เร็วที่สุดในไทย
4. กด Create แล้วรอประมาณ 2 นาที

> Free plan ให้ 2 project ต่อ organization — ถ้าระบบแจ้งว่าเต็ม ให้กด New organization (ฟรี) แล้วสร้าง project ในนั้นแทน

## ขั้นที่ 2 — รัน SQL สร้างตารางทั้งหมด

1. ในโปรเจกต์ใหม่ เมนูซ้าย → **SQL Editor** → **New query**
2. เปิดไฟล์ `asset-verify/schema.sql` คัดลอก**ทั้งไฟล์** วางลงช่อง แล้วกด **Run**
3. ต้องขึ้น `Success. No rows returned` (มีข้อความ notice สีเหลืองได้ ไม่เป็นไร)

ไฟล์นี้สร้างให้ครบในครั้งเดียว: ตาราง `profiles`, `asset_master`, `asset_verify_log`,
ระบบสิทธิ์ (RLS), Realtime และ Storage bucket `asset-files`

## ขั้นที่ 3 — เอาค่าเชื่อมต่อมาใส่ config.js

1. เมนูซ้าย → **Project Settings** (ไอคอนเฟือง) → **API**
2. คัดลอก 2 ค่า:
   - **Project URL** เช่น `https://abcdefghijk.supabase.co`
   - **anon public** key (ข้อความยาวขึ้นต้นด้วย `eyJ...`)
3. เปิดไฟล์ `asset-verify/config.js` แทนที่ 2 บรรทัดนี้:

```js
  SUPABASE_URL: 'https://YOUR-PROJECT-REF.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR-ANON-KEY',
```

> ⚠ ใส่ได้เฉพาะ **anon public** เท่านั้น ห้ามใส่ `service_role` เด็ดขาด (คีย์นั้นข้ามระบบสิทธิ์ทั้งหมด)
> anon key เปิดเผยได้ตามปกติ เพราะ RLS + การ login เป็นตัวคุมสิทธิ์จริง — เหมือนที่ MCR ใช้อยู่

## ขั้นที่ 4 — Deploy ขึ้น Cloudflare Pages (บัญชีเดิม)

> **หมายเหตุสำคัญ**: repo `mcr-stock-count` บน GitHub มี root อยู่ที่โฟลเดอร์ `supabase-web` — ไม่ใช่
> โฟลเดอร์ "Count Stock" ดังนั้นโฟลเดอร์ `asset-verify` **ไม่ได้อยู่ใน repo เดิม** เลือกทางใดทางหนึ่ง:

### ✅ วิธีที่ใช้จริง — เชื่อม GitHub (แก้โค้ดแล้วเว็บอัปเดตเองอัตโนมัติ เหมือน MCR)

**ทำครั้งเดียว:**

1. สร้าง repo ใหม่ที่ https://github.com/new
   - **Repository name**: `asset-verify-brh3`
   - เลือก **Private**
   - **อย่าติ๊ก** Add a README / .gitignore / license (ต้องเป็น repo ว่างเปล่า)
   - กด **Create repository**
2. ในเครื่อง เปิด Git Bash ที่โฟลเดอร์ `asset-verify` แล้วรัน (โฟลเดอร์นี้ init + commit ไว้ให้แล้ว):

```bash
git remote add origin https://github.com/thiraphatsa-hash/asset-verify-brh3.git && git push -u origin main
```

3. Cloudflare → **Workers & Pages** → **Create** → ท้ายหน้าตรง "Looking to deploy Pages?" กด
   **Get started** → **Connect to Git** → เลือก repo `asset-verify-brh3`
   (ถ้า Cloudflare ยังไม่เห็น repo ใหม่ ให้กด **Add account / Configure repositories** แล้วให้สิทธิ์ repo นี้)
4. ตั้งค่า build:
   - **Project name**: `asset-verify-brh3` → ได้ URL `https://asset-verify-brh3.pages.dev`
   - **Production branch**: `main`
   - **Framework preset**: `None`
   - **Build command**: เว้นว่าง
   - **Build output directory**: เว้นว่าง (ไฟล์อยู่ที่ root ของ repo อยู่แล้ว)
5. กด **Save and Deploy**

**ต่อจากนี้ทุกครั้งที่แก้โค้ด** แค่ commit + push แล้ว Cloudflare จะ build ใหม่เองภายใน ~1 นาที:

```bash
git add -A && git commit -m "อธิบายสิ่งที่แก้" && git push
```

> ⚠ **ทุกไฟล์ใน repo นี้ถูกเสิร์ฟเป็นไฟล์สาธารณะบนเว็บ** — ห้ามวางไฟล์รหัสผ่าน คีย์ลับ หรือข้อมูลส่วนตัว
> ในโฟลเดอร์นี้เด็ดขาด ไฟล์ `.gitignore` กันไฟล์ชื่อที่มีคำว่า password/secret/.env และไฟล์ Excel ไว้ให้แล้ว
> แต่ทางที่ปลอดภัยที่สุดคือไม่เก็บไฟล์พวกนั้นไว้ในโฟลเดอร์นี้ตั้งแต่แรก
>
> (`config.js` มี anon key อยู่ — อันนี้เปิดเผยได้ตามการออกแบบของ Supabase เหมือน MCR ไม่ใช่ความลับ)

### ทางสำรอง — อัปโหลดไฟล์ตรงๆ (ไม่ต้องใช้ git)

Cloudflare → **Workers & Pages** → **Create** → **📂 Upload your static files** → ตั้งชื่อ →
ลากเนื้อในโฟลเดอร์ `asset-verify` (ต้องเห็น `index.html` อยู่ชั้นบนสุด ไม่ใช่ `asset-verify/index.html`)
→ **Deploy** · เวลาแก้ไขต้องเข้ามาลากไฟล์ใหม่ทับเองทุกครั้ง

## ขั้นที่ 5 — ตั้งค่า URL สำหรับลิงก์รีเซ็ตรหัสผ่าน

1. กลับไป Supabase → **Authentication** → **URL Configuration**
2. **Site URL**: `https://asset-verify-brh3.pages.dev`
3. **Redirect URLs** เพิ่ม: `https://asset-verify-brh3.pages.dev/reset.html`
4. กด Save

## ขั้นที่ 6 — สร้างบัญชี admin ของคุณ

1. เปิดเว็บที่ deploy แล้ว → แท็บ **สมัครสมาชิก** → กรอกอีเมล + รหัสผ่าน (ใช้อีเมล/รหัสเดียวกับที่ใช้ใน
   MCR ได้ เพื่อให้จำง่าย — แต่เป็นคนละฐานบัญชีกัน การเปลี่ยนรหัสฝั่งหนึ่งไม่กระทบอีกฝั่ง)
2. จะขึ้นหน้า "บัญชีรออนุมัติ" — **ค้างหน้านี้ไว้ ไม่ต้องปิด**
3. กลับไป Supabase → SQL Editor → รันคำสั่งนี้ (แก้อีเมลเป็นของคุณ):

```sql
update profiles set role = 'admin', active = true where email = 'you@example.com';
```

4. ภายใน 8 วินาที หน้าเว็บจะพาเข้าระบบเองอัตโนมัติ

## ขั้นที่ 7 — นำเข้าทะเบียนทรัพย์สิน

1. ในแอป กดแท็บล่างขวา **⚙ จัดการ**
2. หัวข้อ "นำเข้าทะเบียนทรัพย์สิน (Master)" → แตะกรอบอัปโหลด → เลือกไฟล์ `Assets_BRH3__30-7-69.xls`
   (ใช้ไฟล์ .xls ต้นฉบับได้เลย ไม่ต้องแปลงเป็น .xlsx ก่อน)
3. ระบบจะอ่านและแสดงสรุป — ต้องได้ **Fixed Assets 270 · ของเช่า 36 · รวม 306 รายการ**
4. กด **ยืนยันนำเข้า**

> การนำเข้ารอบใหม่จะแทนที่ทะเบียนเดิมทั้งชุด แต่**ประวัติผลตรวจไม่หาย** (คนละตาราง)
> ใช้ตอนมีทรัพย์สินเพิ่ม/ลดแล้วต้องการอัปเดตทะเบียนให้ตรงปัจจุบัน

## ขั้นที่ 8 — เพิ่มบัญชีให้ทีมตรวจ

1. ให้ทีมเข้า URL แล้วกด **สมัครสมาชิก** ด้วยอีเมลของแต่ละคน
2. คุณ (admin) เข้าแท็บ **⚙ จัดการ** → หัวข้อบัญชีผู้ใช้ จะเห็นคนที่รออนุมัติ (กรอบสีส้ม)
3. ใส่**ชื่อที่แสดง** (ชื่อนี้จะถูกบันทึกเป็นชื่อผู้ตรวจในทุก record — ควรใส่ชื่อจริงภาษาไทย)
4. เลือกบทบาท **counter** สำหรับทีมตรวจ แล้วติ๊ก **ใช้งาน**

| บทบาท | ทำอะไรได้ |
|---|---|
| viewer | ดูรายการ + สรุปผล อย่างเดียว |
| counter | บันทึกผลตรวจ สแกน ถ่ายรูป (ใช้กับทีมตรวจหน้างาน) |
| admin | ทุกอย่าง + จัดการบัญชี + นำเข้าทะเบียน + ลบ record ที่บันทึกผิด |

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้า login ขึ้น "ยังไม่ได้ตั้งค่า config.js" | ยังไม่ได้ใส่ URL/anon key ในขั้นที่ 3 หรือใส่ผิด |
| สมัครแล้วขึ้น "Database error creating new user" | schema.sql ยังไม่ได้รัน หรือรันไม่สำเร็จ — รันซ้ำได้ |
| login แล้วค้างที่ "บัญชีรออนุมัติ" | ยังไม่มีใครอนุมัติ — admin เข้าแท็บจัดการแล้วติ๊ก "ใช้งาน" |
| เปิดกล้องไม่ได้ | ต้องเปิดผ่าน https (โดเมน pages.dev) และต้องกดอนุญาตกล้อง — ถ้าเคยกดปฏิเสธไว้ ต้องไปแก้ที่ตั้งค่าเว็บไซต์ในเบราว์เซอร์ |
| บันทึกแล้วขึ้น error สิทธิ์ | บัญชีนั้นเป็น viewer — เปลี่ยนเป็น counter |
| ป้าย "รอส่ง" ไม่ลดลงทั้งที่มีเน็ต | แตะที่ป้ายเพื่อสั่งส่งทันที ถ้ายังไม่หายให้เช็คว่าบัญชีมีสิทธิ์ counter |

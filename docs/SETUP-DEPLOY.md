## ขั้นที่ 2 — รัน SQL สร้างตารางทั้งหมด (2 ไฟล์ ตามลำดับ)

1. ในโปรเจกต์ เมนูซ้าย → **SQL Editor** → **New query**
2. เปิดไฟล์ `asset-verify/schema.sql` คัดลอก**ทั้งไฟล์** วางลงช่อง แล้วกด **Run**
3. **New query** อีกครั้ง → เปิดไฟล์ `asset-verify/asset-rounds.sql` คัดลอกทั้งไฟล์ → **Run**
4. **New query** อีกครั้ง → เปิดไฟล์ `asset-verify/asset-duplicates.sql` คัดลอกทั้งไฟล์ → **Run**
5. **New query** อีกครั้ง → เปิดไฟล์ `asset-verify/asset-counts.sql` คัดลอกทั้งไฟล์ → **Run**
6. ต้องขึ้น `Success` (มีข้อความ notice สีเหลืองได้ ไม่เป็นไร)

- `asset-duplicates.sql` = รองรับ RT code เดียวกันที่ติดอยู่กับของหลายชิ้น (คอลัมน์ `piece_no`)
  ถ้ายังไม่รัน แอปยังบันทึกได้ปกติแต่จะนับเป็นชิ้นเดียวเสมอ
- `asset-counts.sql` = ตาราง `asset_count_log` สำหรับ **โหมดนับจำนวนตามหมวด** (ของที่ไม่ทราบ RT code)
  และเปิดให้ **ผู้ตรวจลบรายการที่ตัวเองบันทึกผิดได้เอง** (เดิมลบได้เฉพาะ admin)
  ถ้ายังไม่รัน ปุ่ม "นับจำนวน" จะขึ้นข้อความเตือนให้รันไฟล์นี้ก่อน ส่วนอย่างอื่นใช้งานได้ตามปกติ

- `schema.sql` = ตาราง `profiles`, `asset_master`, `asset_verify_log`, ระบบสิทธิ์ (RLS),
  Realtime และ Storage bucket `asset-files`
- `asset-rounds.sql` = ระบบ **รอบการตรวจนับ** (ตาราง `asset_sessions` + ผูกทะเบียน/ผลตรวจเข้ากับรอบ)
  ถ้ามีทะเบียนเดิมอยู่แล้ว ไฟล์นี้จะย้ายเข้า "รอบแรก" ให้อัตโนมัติ — รันซ้ำได้ปลอดภัย

> ⚠ ถ้ายังไม่รัน `asset-rounds.sql` แอปจะเปิดได้แต่สร้างรอบตรวจไม่ได้ (ขึ้นข้อความให้รันไฟล์นี้ก่อน)

## ขั้นที่ 3 — เอาค่าเชื่อมต่อมาใส่ config.js

1. เมนูซ้าย → **Project Settings** (ไอคอนเฟือง) → **API**
2. คัดลอก 2 ค่า:
   - **Project URL** เช่น `https://abcdefghijk.supabase.co`
   - **anon public** key (ข้อความยาวขึ้นต้นด้วย `eyJ...`)
3. เปิดไฟล์ `asset-verify/config.js` แทนที่ 2 บรรทัดนี้:

```js
  SUPABASE_URL: 'https://YOUR-PROJECT-REF.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR-ANON-KEY',
```

> ⚠ ใส่ได้เฉพาะ **anon public** เท่านั้น ห้ามใส่ `service_role` เด็ดขาด (คีย์นั้นข้ามระบบสิทธิ์ทั้งหมด)
> anon key เปิดเผยได้ตามปกติ เพราะ RLS + การ login เป็นตัวคุมสิทธิ์จริง — เหมือนที่ MCR ใช้อยู่

## ขั้นที่ 4 — Deploy ขึ้น Cloudflare Pages (บัญชีเดิม)

> **หมายเหตุสำคัญ**: repo `mcr-stock-count` บน GitHub มี root อยู่ที่โฟลเดอร์ `supabase-web` — ไม่ใช่

### ✅ วิธีที่ใช้จริง — เชื่อม GitHub (แก้โค้ดแล้วเว็บอัปเดตเองอัตโนมัติ เหมือน MCR)

**ทำครั้งเดียว:**

1. สร้าง repo ใหม่ที่ https://github.com/new
   - **Repository name**: `asset-verify-brh3`
   - เลือก **Private**
   - **อย่าติ๊ก** Add a README / .gitignore / license (ต้องเป็น repo ว่างเปล่า)
   - กด **Create repository**
2. ในเครื่อง เปิด Git Bash ที่โฟลเดอร์ `asset-verify` แล้วรัน (โฟลเดอร์นี้ init + commit ไว้ให้แล้ว):

```bash
git remote add origin https://github.com/thiraphatsa-hash/asset-verify-brh3.git && git push -u origin main
```

3. Cloudflare → **Workers & Pages** → **Create** → ท้ายหน้าตรง "Looking to deploy Pages?" กด
   **Get started** → **Connect to Git** → เลือก repo `asset-verify-brh3`
   (ถ้า Cloudflare ยังไม่เห็น repo ใหม่ ให้กด **Add account / Configure repositories** แล้วให้สิทธิ์ repo นี้)
4. ตั้งค่า build:
   - **Project name**: `asset-verify-brh3` → ได้ URL `https://asset-verify-brh3.pages.dev`
   - **Production branch**: `main`
   - **Framework preset**: `None`
   - **Build command**: เว้นว่าง
   - **Build output directory**: เว้นว่าง (ไฟล์อยู่ที่ root ของ repo อยู่แล้ว)
5. กด **Save and Deploy**

**ต่อจากนี้ทุกครั้งที่แก้โค้ด** แค่ commit + push แล้ว Cloudflare จะ build ใหม่เองภายใน ~1 นาที:

```bash
git add -A && git commit -m "อธิบายสิ่งที่แก้" && git push
```

> ⚠ **ทุกไฟล์ใน repo นี้ถูกเสิร์ฟเป็นไฟล์สาธารณะบนเว็บ** — ห้ามวางไฟล์รหัสผ่าน คีย์ลับ หรือข้อมูลส่วนตัว
> ในโฟลเดอร์นี้เด็ดขาด ไฟล์ `.gitignore` กันไฟล์ชื่อที่มีคำว่า password/secret/.env และไฟล์ Excel ไว้ให้แล้ว

## ขั้นที่ 6 — ตั้งค่าการเข้าสู่ระบบ + สร้างบัญชี admin

### 6.1 ตรวจสวิตช์ผู้ให้บริการอีเมล

Supabase → **Authentication** → **Sign In / Providers** → คลิกแถว **Email**

- **Enable email provider** ต้อง 🟢 **เปิด** (ถ้าปิดจะขึ้น "Email logins are disabled")
- ถ้าเจอสวิตช์ **Confirm email** ให้ปิด — แต่ **Supabase บางเวอร์ชันไม่มีสวิตช์นี้แล้ว ไม่เป็นไร**
  เพราะแอปจัดการให้เองแล้ว: เวลา admin กดอนุมัติบัญชี (หรือติ๊ก "ใช้งาน") ระบบจะยืนยันอีเมล
  ให้ผู้ใช้คนนั้นอัตโนมัติผ่านฟังก์ชัน `admin_confirm_email` ใน `auth-tools.sql`

> ระบบนี้ใช้การอนุมัติโดย admin เป็นตัวคุมสิทธิ์อยู่แล้ว จึงไม่ต้องให้ผู้ใช้กดลิงก์ยืนยันในอีเมลซ้ำ
> (อีเมลของ Supabase แบบฟรีจำกัดไม่กี่ฉบับต่อชั่วโมง จะเป็นคอขวดตอนเปิดบัญชีให้ทีมหลายคนพร้อมกัน)

### 6.2 สมัครบัญชีของคุณ

เปิดเว็บ → แท็บ **สมัครสมาชิก** → กรอกอีเมล + รหัสผ่าน (กดไอคอน 👁 ท้ายช่องเพื่อดูว่าพิมพ์ถูกไหม)
→ จะขึ้นหน้า "บัญชีรออนุมัติ" ให้ค้างหน้านั้นไว้

### 6.3 รัน auth-tools.sql

SQL Editor → วางไฟล์ `asset-verify/auth-tools.sql` ทั้งไฟล์ → **Run** ไฟล์นี้ทำ 4 อย่าง:

1. ติดตั้งฟังก์ชัน `admin_delete_user` (ให้ admin ลบบัญชีจากในแอปได้)
2. ติดตั้งฟังก์ชัน `admin_confirm_email` (แอปเรียกอัตโนมัติตอนอนุมัติบัญชี — แก้ "Email not confirmed" ถาวร)
3. ยืนยันอีเมลให้ทุกบัญชีที่ค้างอยู่ตอนนี้
4. ตั้งบัญชีในรายการเป็น admin + เปิดใช้งาน — **แก้อีเมลในไฟล์ให้เป็นของคุณก่อนรัน**

## ขั้นที่ 7 — สร้างรอบตรวจนับรอบแรก

1. ในแอปหน้าหลัก กด **＋ สร้างรอบตรวจ**
2. แตะกรอบอัปโหลด → เลือกไฟล์ `Assets_BRH3__30-7-69.xls`
   (ใช้ไฟล์ .xls ต้นฉบับได้เลย ไม่ต้องแปลงเป็น .xlsx ก่อน)
3. ระบบอ่านไฟล์แล้วแสดงสรุป — ต้องได้ **306 รายการ (Fixed Assets 270 · ของเช่า 36)**
   และเติมรหัสโครงการ/Cost center ให้อัตโนมัติจากในไฟล์
4. ตรวจ/แก้ฟอร์ม: โครงการ, ชื่อรอบ, วันที่ตรวจ, ผู้รับผิดชอบ → กด **สร้างรอบและนำเข้าทะเบียน**

> **1 รอบ = 1 ไฟล์ที่อัปโหลด** — แต่ละรอบเก็บทะเบียนของตัวเอง ไม่กระทบรอบอื่น เหมือนระบบ MCR
> รอบใหม่ของโครงการเดิมก็แค่อัปโหลดไฟล์อีกครั้ง · ลบรอบได้จากปุ่ม 🗑 บนการ์ดหน้าหลัก
> (ลบรอบ = ลบทะเบียนและผลตรวจของรอบนั้นทั้งหมด กู้คืนไม่ได้)

## ขั้นที่ 8 — เพิ่มบัญชีให้ทีมตรวจ

1. ให้ทีมเข้า URL แล้วกด **สมัครสมาชิก** ด้วยอีเมลของแต่ละคน
2. ฝั่งคุณ (admin) ระบบจะ**แจ้งเตือนอัตโนมัติ**: มีป้ายเลขสีแดงบนปุ่ม ⚙ จัดการ และเด้งกล่อง
   "🔔 มีคำขอใช้งานใหม่" ให้กด **✓ อนุมัติ** (ได้บทบาท counter ทันที) หรือ **✕ ปฏิเสธ** (ลบบัญชีทิ้ง)
   — ระบบเช็คคำขอใหม่ให้ทุก 1 นาทีระหว่างเปิดแอปอยู่
3. เข้าแท็บ **⚙ จัดการ** เพื่อใส่**ชื่อที่แสดง** (ชื่อนี้จะถูกบันทึกเป็นชื่อผู้ตรวจในทุก record —
   ควรใส่ชื่อจริงภาษาไทย), ปรับบทบาท, ปิดการใช้งาน หรือกด 🗑 ลบบัญชีถาวร
   (ลบบัญชีแล้ว**ผลตรวจที่คนนั้นเคยบันทึกยังอยู่ครบ** เพราะเก็บชื่อผู้ตรวจเป็นข้อความ)

| บทบาท | ทำอะไรได้ |
|---|---|
| viewer | ดูรายการ + สรุปผล อย่างเดียว |
| counter | บันทึกผลตรวจ สแกน ถ่ายรูป (ใช้กับทีมตรวจหน้างาน) |
| admin | ทุกอย่าง + จัดการบัญชี + นำเข้าทะเบียน + ลบ record ที่บันทึกผิด |

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้า login ขึ้น "ยังไม่ได้ตั้งค่า config.js" | ยังไม่ได้ใส่ URL/anon key ในขั้นที่ 3 หรือใส่ผิด |
| สมัครแล้วขึ้น "Database error creating new user" | schema.sql ยังไม่ได้รัน หรือรันไม่สำเร็จ — รันซ้ำได้ |
| login ขึ้น **"Email not confirmed"** | ปิดสวิตช์ **Confirm email** (ขั้นที่ 6.1) แล้วรัน `auth-tools.sql` หนึ่งครั้ง |
| login ขึ้น **"Email logins are disabled"** | เผลอปิดสวิตช์ **Enable Email provider** — เปิดกลับ (ขั้นที่ 6.1) |
| สมัครแล้วขึ้น "you can only request this after N seconds" | Supabase จำกัดส่งอีเมล 1 ฉบับ/นาที — แปลว่าการสมัครครั้งแรกสำเร็จไปแล้ว ให้ไปแท็บเข้าสู่ระบบแทน |
| SQL ขึ้น `relation "asset_master" does not exist` | รันผิดโปรเจกต์ — เช็คชื่อโปรเจกต์มุมบนซ้ายให้เป็น `asset-verify-brh3` (URL `onwioowjaafxobuubhwf`) |
| SQL รันแล้วได้ `0 rows` ทั้งที่ควรมีผล | มีการลากเลือกข้อความบางส่วนไว้ ปุ่มจะเป็น **Run selected** — กด `Ctrl+A` เลือกทั้งหมดก่อน Run |
| กด 🗑 ลบบัญชีแล้วขึ้นว่ายังไม่ได้ติดตั้งฟังก์ชัน | ยังไม่ได้รัน `auth-tools.sql` |
| login แล้วค้างที่ "บัญชีรออนุมัติ" | ยังไม่มีใครอนุมัติ — admin เข้าแท็บจัดการแล้วติ๊ก "ใช้งาน" |
